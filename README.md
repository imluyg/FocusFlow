# FocusFlow 效率追踪器

FocusFlow 是一款 Windows 键鼠活跃度统计与效率分析工具：实时追踪键盘/鼠标/滚轮活动，
提供排行榜、趋势图、小时/星期分布等统计视图，并集成番茄钟、护眼休息、定时任务、
记账本等插件。

## 功能特性

- **实时统计**：今日活跃次数、当前速度（次/分），后台 500ms 刷新，UI 零阻塞
- **周期统计**：今日 / 7天 / 15天 / 30天 / 1年 / 总计，周期选择自动记忆（重启保持）
- **多视图**：键鼠排行、分组统计、趋势图（7/30 天）、小时分布、星期分布
- **应用排行**：前台应用使用时长（与活跃时长同口径，可下钻查看周期占比）
- **设备排行**：区分不同键盘/鼠标的独立统计（Raw Input 侧信道，按设备实例归属，
  支持「全部 / 鼠标 / 键盘」筛选；换键鼠后新旧设备各自计数）
- **悬浮窗**：透明置顶小窗实时显示活跃与速度，可拖动、双击打开主界面、位置记忆
- **系统托盘**：实时 tooltip（今日活跃/速度）、暂停时切换图标、左键呼出主界面
- **全局热键**：`Ctrl+Shift+F` 显示/隐藏主窗口，组合键与开关均可在设置中修改
  （**默认关闭**，需在设置页勾选"启用热键"后生效）
- **插件系统**（Lua）：番茄钟、定时任务、记账本、Edge 历史记录、统计概览
- **数据管理**：导入旧版数据、导出 CSV/HTML 报告、数据库压缩、自动备份轮转
- **外观**：液态玻璃风格（渐变背景 + 大圆角卡片），浅色/深色主题，Segoe UI 字体

## 项目结构

```
crates/
  core/      核心库：数据库、键鼠监听、设备统计（Raw Input）、统计、配置、Lua 插件宿主
  cli/       命令行工具：统计查询 / 导出 / 清空
desktop/     Tauri v2 桌面应用（当前主版本）
  src/       Rust 后端：命令、状态、托盘、热键、插件交互、导出
  ui/        前端（HTML/CSS/JS ES module，无构建步骤）
  capabilities/   Tauri 能力配置（ACL 权限）
  tauri.conf.json 窗口/打包配置
dist/       打包输出（绿色版 + NSIS 安装包，不入库）
```

## 构建

要求：Rust 1.80+、Node.js（仅 Tauri CLI 用 npx）、MSVC Build Tools、Windows 10/11。

```bash
# 绿色版（dist\FocusFlow\FocusFlow.exe）
build_tauri.bat

# NSIS 安装包（desktop/target/release/bundle/nsis/ 下）
desktop\build_nsis.bat
```

运行：直接双击 `dist\FocusFlow\FocusFlow.exe`，或安装 NSIS 安装包。
数据（键鼠记录、插件库）存放在程序目录 `data/`，备份在 `backup/`。
程序目录的定位优先级：`FOCUSFLOW_APP_DIR` 环境变量 > exe 所在目录（release 版）> 当前工作目录；
快捷方式的"起始位置"不影响数据落点。配置损坏时原文件会被备份为 `config.ini.corrupt-<时间戳>` 后重建。

## 开发

- 后端：`cargo build` / `cargo test --workspace` / `cargo clippy --workspace`；
  格式与 lint 在 CI（`.github/workflows/ci.yml`）强制执行。
- 前端：`desktop/ui/` 纯原生 ES module（无构建步骤）——`js/main.js` 为入口，
  主题变量唯一来源为 `tokens.css`。
- 插件：`crates/core/plugins/` 为源码，构建时复制到运行目录 `plugins/`（热重载）。

## 常见问题

- **启动后看不到主窗口**：默认启动进托盘，点击托盘图标或按全局热键呼出。
- **悬浮窗被任务栏遮挡**：程序每 500ms 重申置顶，最多 0.5 秒内自动浮回。
- **Edge 历史记录为 0**：Edge 运行时锁定数据库，程序自动复制副本读取；
  若仍为 0 请确认 Edge 安装路径为默认位置。
- **定时任务无法添加某个程序**：定时任务的目标受白名单限制（只放行常见用户应用，
  解释器与系统程序一律禁止，避免插件借此启动任意命令）。需要放行其它程序时，
  在 `config.ini` 的 `[scheduler]` 段加 `allow_extra = 你的程序.exe`。
- **应用总时长比今日活跃时长小**：两者是同一口径（键鼠事件间隔 ≤60 秒算连续活跃），
  时长都在事件发生时归属，差额只来自「当时没有识别到前台应用」的时段
  （程序刚启动的几秒、锁屏、`[app_stats] exclude` 命中的进程）。
  若差距很大，先确认 `config.ini` 里 `[app_stats] enabled` 没有被改成 false。
- **导入旧数据不生效**：设置 → 数据操作 → 导入旧数据，选择旧版程序的 `data` 目录
  （导入结果会显示各年度条数与附属数据库）。
- **更换鼠标/键盘后统计怎么算**：换设备**不需要任何设置**。键鼠排行走系统级低级钩子
  （所有设备汇成一路），换键鼠后统计连续不变；设备排行走 Raw Input 侧信道，按设备实例
  分别计数，新设备从第一次输入开始独立累计，登记表在设备首个事件时写入一次。
- **设备排行数字和键鼠排行对不上**：这是**两套独立口径**，不追求相等。设备次数 =
  键盘按下 + 鼠标左/右/中键按下 + 滚轮，只统计真实硬件输入（脚本/宏用 SendInput
  合成的输入不产生 Raw Input，天然不计）；且不做长按去重与修饰键过滤。
- **设备名看不懂 / 想改名**：设备排行每行点「改名」输入自己的名字（如「罗技 G304」），
  按回车保存；有别名时原名会作为副标题保留，点「还原」可恢复自动名。
  别名存在 `data/device_aliases.json`（纯文本，可直接手改），先在
  `--rename-device` 前用 `focusflow-cli --device-keys` 查设备标识也行：
  `focusflow-cli --rename-device "24AE/1464" "新鼠标"`。
  同名型号换 USB 口后实例路径会变，别名按 VID/PID 型号回退仍然生效（同型号出现
  多个不同别名时该回退自动停用，避免张冠李戴）。
- **设备排行里同一只鼠标出现多行**：无线接收器或蓝牙设备在系统里会暴露多个 HID 集合
  （鼠标接口 + 键盘/多媒体接口），各占一行；只有真正产生过输入的接口才有数据。
  没有 VID/PID 的设备（触控板、PS/2、ACPI 键盘）显示为「设备名 · 实例短标识」。
- **关掉设备统计**：`config.ini` 的 `[device_stats]` 段设 `enabled = false`（重启生效）。
  设备维度数据从该功能上线后开始积累，此前的历史数据无法回溯归属到具体设备。
- **插件停用了，为什么备份里还有它的数据**：已停用插件的数据文件不再参与备份
  （其库不再被写入，没必要占轮转名额）。想让停用插件的数据也一起备份，
  在 `config.ini` 的 `[database]` 加 `backup_disabled_plugins = true`。
- **跨年时会发生什么**：程序启动时若发现当前库里有往年数据（旧版单库迁移、异常终止回放等），
  会做**跨年归档** —— 把往年数据搬进各自年份的 `focusflow_<年>.db`，然后把源库 VACUUM 一次。
  归档与备份开关**无关**，照常执行；但归档前会**自动留一份「归档前快照」**（不受两个备份开关影响），
  因为 WAL 模式下跨库事务整体不原子，崩溃可能造成"目标库已加、源库未删"，
  下次启动重复归档会让计数翻倍。数据平时按年份分库存在，跨年不会丢数据；
  关掉两个备份开关只影响"多一份可回滚的快照"，不影响归档本身。`[database] yearly_archive = false`
  可以完全关掉归档（不推荐）。
- **备份会不会把好数据顶掉（保存了异常数据怎么办）**：备份按**分层保留**，不是"只留最新 N 份"：
  最近 5 份全留 + 每天一份（7 天）+ 每周一份（4 周）+ 每月一份（6 个月）。
  所以即使异常数据连续备份（一天内多开关几次程序），仍然留着「约 1 天前 / 1 周前 / 1 个月前」
  的干净快照可回滚。此外每次备份会做**异常体检**：与上一份备份对比总量与天数，
  骤降一半以上 / 涨到 4 倍以上 / 天数明显减少时，当次**冻结轮转（不删任何旧备份）**，
  并在 `backup/` 写一份 `SUSPECT-<时间戳>.txt` 说明、设置页显示红色提示。
  保留档位可在 `config.ini` 的 `[database]` 调整：`max_backups`（近端份数）、
  `backup_keep_daily` / `backup_keep_weekly` / `backup_keep_monthly`。
- **怎么关掉自动备份**：设置 → 数据备份 里可分别关闭「退出时自动备份」与「运行中定时备份」
  （改动立即生效，无需重启）；也可以直接改 `config.ini` 的 `[database]`：
  `backup_on_exit = false`、`online_backup_interval_hours = 0`。
  命令行可用 `focusflow-cli --backup` 手动备份一次。清空/清理数据前的兜底快照始终保留。
  备份文件是**单个自包含文件**（rollback journal、无 `-wal`/`-shm` 残留），
  可直接复制到别处或只读介质打开。
